# Libredesk 二次开发方案（中国市场网站客服）

- 基线：上游 `abhinavxd/libredesk` `main`，提交 `f4916f41`（2026-09-17），对应发布 v2.8.0
- 本地仓库：`F:\claude bf\openclash ssh\libredesk`
- 文档状态：v1，2026-09-17。任务拆分见同目录 `任务分工.md`

## 1. 目标与范围

给一个面向中国市场的网站提供客服能力，分三层：

| 层 | 要求 | 本方案的判断 |
| --- | --- | --- |
| 未登录访客客服 | 网站任意页面能弹聊天窗与客服对话 | **上游已具备**，只需配置 + 中文化 |
| 已登录用户客服 | 用户登录网站后，客服端能认出是谁、看到其资料，会话跨设备延续 | **上游已具备**（JWT 身份交换），只需网站侧接入 |
| 每个功能做成插件，可开关 | 管理后台一键启停 | **上游没有**，需要新建「功能模块」层 |
| 用户之间对话 | 网站用户互聊 | **本期不做，只记录**，见第 6 节 |

不在范围内：改造上游的邮件/AI/帮助中心逻辑；做移动 App。

## 2. 现状盘点

### 2.1 架构

- 后端：Go 1.26，`fasthttp` + `fastglue` 路由，`sqlx` + Postgres 17，Redis 7（会话/队列/WS 广播），`koanf` 配置，`stuffbin` 把前端产物打进单二进制。289 条路由全在 `cmd/handlers.go`。
- 前端：`frontend/` 是 pnpm 单仓，两个 Vite 应用：`apps/main`（客服后台，Vue 3）和 `apps/widget`（嵌入网站的聊天挂件，Vue 3）。共享 UI 在 `frontend/shared-ui`。
- 依赖注入点：`cmd/main.go` 的 `App` 结构体，每个业务域一个 `Manager`（`internal/<域>/`），handler 通过 `r.Context.(*App)` 取用。
- 鉴权：`cmd/middlewares.go` 的 `auth()` / `perm(handler, "资源:动作")`（Casbin），挂件侧是 `cmd/widget_middleware.go` 的 `validateWidgetInbox()` / `widgetAuth()`。
- 设置：`settings` 表，`key/value(jsonb)`，`internal/setting` 读写，`cmd/config.go` 启动时把 DB 设置合并进 koanf。新增开关就是往这张表加键。
- 构建/测试：`make build`（前端两个 app + Go）；`make test` = `go test ./...` + `pnpm test:run`（vitest）；Cypress e2e 在 `frontend/cypress/`。后端集成测试需要 `make test-db` 起 Postgres 5433。

### 2.2 i18n 现状（本次已处理一部分）

- 机制：**整站一个 JSON 语言包** `i18n/<code>.json`，后端 `GET /api/v1/lang/{code}` 下发，主应用和挂件都从这里取。后端自身的报错文案也用同一包（`app.i18n.T(...)`）。语言由设置 `app.lang` 决定（默认 `en-US`），挂件跟随。
- `zh-CN.json`：**已补全到 1603/1603 键**（本次从 1092 补了 519 条，见 git diff）。剩余 16 条与英文相同的是专有名词/网址/占位符示例，不应翻。
- **仍是英文硬编码、需要处理**：
  - `static/email-templates/{base,welcome,reset-password}.html`（邮件）
  - `static/public/web-templates/`：`csat.html`、`csat-widget.html`、`error.html`、`info.html`、`index.html`，以及 `help/{classic,docs}/*.html` 帮助中心页面（这些是 Go 模板，部分已用 `{{ T "key" }}`，部分是裸英文，要逐个看）
  - `schema.sql` 种子数据：默认邮件模板 `INSERT INTO templates`（8 条，行 1081–1266）、AI 编辑器预设提示词（行 1009–1014）、默认设置 `app.timezone = Asia/Kolkata`、`app.site_name = libredesk`
- ⚠️ 上游 `.github/workflows/i18n-guard.yml` **会拒绝任何直接改非 en-US 语言包的 PR**（翻译走 Crowdin）。fork 里要么删掉这个 workflow，要么给 PR 打 `allow-i18n-edit` 标签。**向上游回馈中文翻译只能走 Crowdin。**

### 2.3 已具备、可直接用的能力

- 在线聊天挂件：`static/widget.js`（645 行，无依赖）注入 iframe，聊天 UI 是 `apps/widget`。支持访客 / 用户两种模式、聊天前表单、营业时间、未读角标、页面跟踪、CSAT。
- 已登录用户识别：见第 3 节。
- 管理后台：收件箱、团队、角色权限、宏、标签、自动化、SLA、视图、报表、帮助中心、AI 助手。

## 3. 未登录 / 已登录用户客服接入（不需要改上游代码）

### 3.1 流程

```
网站后端                                Libredesk
   │  用户登录后，用收件箱 secret 签 JWT        │
   │  ───────────────────────────────────►   │
网站前端                                     │
   │  LibredeskWidget.setUser(jwt)           │
   │  ───► POST /api/v1/widget/chat/auth/exchange {jwt}
   │                                          │ verifyStandardJWT(jwt, inbox.secret)
   │                                          │ resolveOrCreateExternalContact(claims)
   │  ◄─── session token（cookie）            │
   │  之后所有挂件请求走 widgetAuth()          │
```

- 校验代码：`cmd/chat.go:349 handleAuthExchange`，`cmd/chat.go:936 verifyStandardJWT`（HMAC，密钥是收件箱的 `secret` 字段，后台「收件箱 → 编辑 → 安全」页可见）。
- 未登录访客：不调 `setUser`，挂件自动用 `visitorToken` cookie 建匿名联系人。
- 登出：`LibredeskWidget.logout()` 清 cookie 并通知 iframe。

### 3.2 JWT claims（`cmd/chat.go:59 Claims`）

| 字段 | 必填 | 上限 | 说明 |
| --- | --- | --- | --- |
| `external_user_id` | 是 | `maxExternalUserIDLength` | 网站用户 ID，去重依据 |
| `email` | 是 | `maxEmailLength` | ⚠️ 上游强制要邮箱。国内站点很多用户只有手机号，见 3.4 |
| `first_name` | 是 | `maxNameLength` | 中文名可整个放这里，`last_name` 留空 |
| `last_name` | 否 | 同上 | |
| `phone_number` / `phone_number_country_code` | 否 | | 国家码填 `86` |
| `contact_custom_attributes` | 否 | | 任意键值，会存到联系人自定义属性（后台需先建对应属性） |

站点侧签发示例（Node）：

```js
import jwt from 'jsonwebtoken'
const token = jwt.sign({
  external_user_id: String(user.id),
  email: user.email || `${user.id}@no-email.local`,   // 见 3.4
  first_name: user.nickname,
  phone_number: user.mobile, phone_number_country_code: '86',
  contact_custom_attributes: { vip_level: user.vip, register_at: user.createdAt },
  exp: Math.floor(Date.now()/1000) + 3600,
}, INBOX_SECRET, { algorithm: 'HS256' })
```

### 3.3 网站侧嵌入

后台「收件箱 → 编辑 → 安装」页给出的 `<script>` 片段，本质是加载 `https://<libredesk域名>/widget.js?inbox=<uuid>`。SPA 站点在路由切换后不必重载，`widget.js` 自带 pushState 监听。

### 3.4 需要二开的两个点（属于「已登录用户」层，但要动代码）

1. **邮箱必填放宽**：`handleAuthExchange` 在 `claims.Email == ""` 时返回 400。国内站点应允许「手机号或邮箱至少一个」。改法：`cmd/chat.go:379` 的判断改为二者取一；`resolveOrCreateExternalContact` 里以 `external_user_id` 为主键去重（先确认它当前是否用 email 去重）。
2. **联系人资料回显**：客服端联系人侧栏已能显示自定义属性，但字段名是英文键。把常用字段（会员等级、注册时间、最近订单）预先在后台「自定义属性」里建好中文显示名，写进部署脚本。

## 4. 插件化：功能模块开关层（新建）

上游没有插件系统。不要做真正的动态加载（Go 静态链接、前端也是打包产物，动态加载成本极高且和上游升级冲突）。做的是**编译进去、运行时可开关**的「功能模块」：

### 4.1 数据

`settings` 表新增键，命名 `feature.<模块名>.enabled`（jsonb boolean），迁移文件放 `internal/migrations/vX.Y.Z.go`（仿现有写法）。首批模块：

| 键 | 默认 | 控制范围 |
| --- | --- | --- |
| `feature.livechat.enabled` | true | `/widget*`、`/api/v1/widget/*`、`/widget/ws` |
| `feature.helpcenter.enabled` | false | `/api/v1/help-centers/*`、`/api/v1/public/help-centers/*`、帮助中心页面 |
| `feature.ai.enabled` | false | `/api/v1/ai/*`（38 条）、Copilot、AI 助手 |
| `feature.csat.enabled` | true | `/csat/*`、会话关闭时的满意度推送 |
| `feature.email_channel.enabled` | false | 邮件收件箱的 IMAP 轮询与 SMTP 发送 |
| `feature.user_chat.enabled` | false | 用户间对话（本期只留键，不实现，见第 6 节） |

### 4.2 后端

- `internal/feature/feature.go`：`Manager`，启动时从 settings 读所有 `feature.*` 键进内存 `map[string]bool`，提供 `Enabled(name) bool`，并在 settings 更新时刷新（复用现有 settings 更新的钩子）。
- 中间件 `cmd/middlewares.go` 新增 `feat(name string, h) h`：关闭时返回 `404` + i18n 文案 `globals.messages.featureDisabled`（en-US / zh-CN 两个语言包都加）。**用 404 不用 403**，避免暴露有哪些模块。
- `cmd/handlers.go` 里给对应路由包一层 `feat("livechat", ...)`。这是唯一要大面积碰上游文件的地方，做成**按前缀分组注册**（一个 helper 里把同模块路由集中注册），减少与上游合并冲突。
- 后台任务：`feature.email_channel` 关闭时 `inbox.Manager` 不启动 IMAP 轮询（`internal/inbox/inbox.go` 启动循环处加判断）。
- 挂进 `App` 结构体：`feature *feature.Manager`。

### 4.3 前端

- `GET /api/v1/settings/general` 的返回里带上 `features: {livechat: true, ...}`（改 `handleGetGeneralSettings`）。
- `apps/main`：`stores/` 加 `useFeatureStore`，路由守卫和侧边栏菜单按开关隐藏；管理后台加「功能模块」页（`views/admin/features/`），每项一个开关 + 一句说明，调用 `PUT /api/v1/settings/general`。
- `apps/widget`：`livechat` 关闭时 `GET /api/v1/widget/chat/settings` 返回 404，挂件应静默不渲染（不是报错）。

### 4.4 与上游升级的关系

- 所有新增文件放 `internal/feature/`、`frontend/apps/main/src/views/admin/features/`、`docs-cn/`，上游合并零冲突。
- 会碰上游的文件只有：`cmd/handlers.go`（包中间件）、`cmd/main.go`（注入）、`cmd/middlewares.go`（加 `feat`）、`cmd/settings.go`（返回 features）、`internal/inbox/inbox.go`（跳过轮询）、两个语言包。每处改动加 `// [cn-fork]` 注释，方便合并时 grep。

## 5. 中国市场适配清单

按重要性排序，每条标注是「配置」还是「代码」：

1. **中文化**（代码）：第 2.2 节列出的模板与种子。默认 `app.lang = zh-CN`、`app.timezone = Asia/Shanghai`、`app.site_name` 由部署脚本设。
2. **邮箱非必填**（代码）：3.4-1。
3. **手机号优先展示**（代码，小）：客服端联系人卡片把手机号提到邮箱前面；聊天前表单默认字段改为「称呼 + 手机号」。
4. **去掉海外依赖**（配置/代码）：
   - 后台登录页与收件箱 OAuth 的 Google / Microsoft 入口按 `feature.oidc_google/microsoft` 隐藏（或直接不配就不显示，先确认）。
   - 帮助中心社交链接默认项加微信公众号、微博；`helpCenter.social.*` 语言包加对应键。
   - 挂件 `editor.tooltip.youtube` 之类保留即可，但国内用不了，文档里说明。
   - 前端有无引用 Google Fonts / 海外 CDN：`grep -rn "fonts.googleapis\|cdn\." frontend/apps` 确认，有则本地化。
5. **通知渠道**（代码，中）：上游只有邮件 + 浏览器推送。国内客服团队常用企业微信 / 钉钉 / 飞书群机器人，做成 `notification.webhook` 类型（上游已有 `internal/webhook` 可复用），作为 `feature.im_notify` 模块。**二期。**
6. **备案与域名**：Libredesk 域名、挂件 `widget.js` 的加载域名、上传文件的访问域名三者都要能在国内直连。挂件 JS 建议走国内 CDN。
7. **移动端挂件**：`widget.js` 已有 `isMobile` 分支，需要在微信内置浏览器实测（微信 WebView 对 iframe + cookie 的限制，`SameSite=None; Secure` 必须）。

## 6. 用户之间对话（本期只记录）

需求：网站用户 A 与用户 B 互发消息，作为 `feature.user_chat` 模块。

不做的原因：Libredesk 的数据模型是「联系人 ↔ 客服」的会话，`conversations` 表一端是 `contact_id`、另一端是 `assigned_user_id/team_id`，权限模型也是客服视角。用户间对话要么硬塞进这套模型（把用户 B 当客服，会污染报表、SLA、分配逻辑），要么另起一套表和 WS 通道。后者才是对的，但工作量与一个独立 IM 相当。

留给二期的记录：

- 复用点：`internal/ws`（WS Hub）、`widgetAuth` 的会话机制、`media` 上传、消息渲染组件。
- 新建：`user_threads`、`user_thread_messages` 表；`/api/v1/widget/threads/*` 路由；挂件里第三个 Tab「私信」。
- 前置：3.4-1 做完（用户身份稳定），且明确产品规则（谁能给谁发、举报/拉黑、消息保留期）。

- `make test` 全绿；`go vet ./...` 无新警告；`pnpm lint` 无新错误。

## 9. 风险

- 上游迭代快（v2.8.0 到 main 一个月内几十次提交），`cmd/handlers.go` 是冲突高发区，4.2 的「按前缀分组注册」是唯一缓解。
- 邮箱非必填会影响上游依赖 email 的地方（通知、CSAT 邮件、联系人去重），改之前要 `grep -rn "contact.Email\|\.Email\b" internal/conversation internal/csat internal/notification` 逐个确认。
- Redis 是硬依赖（会话 token 存 Redis），不可去掉。

## 10. 相对 Chatwoot 的功能缺口（决定要不要补、补哪些）

对照 Chatwoot v4.17 与 Libredesk v2.8（代码核实：`grep -ril <关键词> internal cmd`）。分三档：

**A. 对本项目有用、值得补的**

| 缺口 | Chatwoot 有 | Libredesk 现状 | 建议 |
| --- | --- | --- | --- |
| 主动消息 / 营销触达（Campaigns） | 按 URL、停留时长、访客属性主动弹消息；一次性群发 | 无（`campaign`/`proactive` 0 处） | 做成 `feature.campaign`，二期。挂件已有页面跟踪（`onPageChange`），触发点现成 |
| 多渠道收件箱 | WhatsApp、Messenger、Instagram、Telegram、Line、Twilio 短信、API 渠道 | 只有邮件 + 网页聊天 | 海外渠道对中国市场无意义；**该补的是微信公众号/小程序客服、企业微信**。用上游 `internal/inbox/channel/` 的接口（`Identifier` / `Send` / `Receive`）加 `wechat` 渠道，三期 |
| 已读回执 / 客户正在输入 | 双向 | 有 `typing`（7 处）；无已读回执 | 小改：`messages` 加 `seen_at`，WS 推一个事件。一期可做 |
| 客服接待上限 / 轮询分配 | 每客服最大会话数、round-robin | 有自动分配（`autoassigner`），无容量上限 | `feature.capacity`，`agents` 加 `max_open_conversations`，分配器跳过满员者。一期 |
| 联系人拉黑 | 有 | 无 | 挂件侧按 `external_user_id` / 访客 token 拒绝发消息。一期，小 |
| 消息翻译 | Google Translate 集成 | 无 | 用 `feature.ai` 的模型做翻译即可，不单独做 |

**B. Libredesk 已有、不用补**

宏（Chatwoot 叫 Canned responses + Macros，这里 `macro` 11 处）、延后（snooze）、CSAT、SLA、自动化规则、标签、团队、角色权限、视图、报表、帮助中心、Webhook、联系人导入导出、活动日志（`internal/activity_log`）、SSO（`internal/oidc`）、AI 助手 + Copilot（对应 Chatwoot 的 Captain）、聊天前表单、营业时间、附件上传、表情。

**C. Chatwoot 有、本项目不需要的**

多工作区 / 多品牌（Libredesk 单租户，够用）、iOS/Android 客服 App（Libredesk 后台是响应式网页，微信内打开可用；真要 App 是独立项目）、Slack / Linear / Shopify / Dyte 视频等集成、WhatsApp 模板消息、语音通话。

**D. 反过来 Libredesk 比 Chatwoot 强的（说明选型没错）**

单二进制 71 MB 对 2.56 GB 镜像；空载内存几十 MB 对 1 GB；无 Ruby/Sidekiq 运维负担；AI 工具调用、客户身份验证码、FAQ 自学习是 Chatwoot 社区版没有的。

**结论**：一期补 A 表里的「已读回执、接待上限、拉黑」三项（都小）；campaign 二期；微信渠道三期单独立项。
